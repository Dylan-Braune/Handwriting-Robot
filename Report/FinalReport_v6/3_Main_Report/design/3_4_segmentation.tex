\subsection{Page conditioning and line segmentation}
\label{sec:segmentation}

This subsection turns a photograph of a handwritten page into clean, deskewed, white-background line images for the text recogniser of Section~\ref{sec:textrec} and the writer classifier of Section~\ref{sec:writerid} (functional units FU~2.1 and FU~2.2; requirement R2). It is ordered as the data flows: the array primitives the rest of the block is built from, lighting and binarisation, deskew, the measurement of the scale unit, removal of what is not handwriting, the line centres, and finally the seam cut and crop.

The deployed implementation is \texttt{SegmentLean.py}, eleven functions in about 570 lines behind a single entry point, \texttt{SegmentLines(path)}. The web server, the style-profile builder and the writer-classifier trainer all call that same entry point, so training pages are cut by exactly the code that cuts a page during normal use. Published methods are cited where they are used, and the rules around them are plain array arithmetic written for this project. No part of this block resamples through an imaging library: every operation that changes a pixel value is performed by the project's own module, implementing Equation~\ref{eq:seg-resize} directly; the library is used only to read the file from disk and to write the optional debug overlay.

\subsubsection{Design goals and the vocabulary of a text line}

A flat-bed scan can be conditioned by grey conversion, binarisation and bounding-box line separation, which is what published pipelines do~\cite{hemanth2022,chen2023}. A photograph is harder: it adds uneven illumination, the surroundings of the sheet, skew, printed rules, edge slivers, creases, and lines that touch each other. The block therefore has three design goals:

\begin{enumerate}
\item It must work at any camera resolution and any handwriting size \textbf{without manual tuning}.
\item It must \textbf{never delete handwriting} in order to remove a nuisance.
\item It must keep \textbf{as few fixed constants as possible}.
\end{enumerate}

All three are met by one decision: letting the page set its own scale. The photograph is reduced $2{:}1$ per axis by box averaging, and the \emph{line pitch} $P$ is measured on that working image (Section~\ref{sec:seg-pitch}), after which almost every threshold in the block is a multiple of $P$ rather than an absolute pixel count. Goal~3 is therefore testable rather than aspirational, and Section~\ref{sec:seg-const} discharges it: of the thirty-odd constants in the block, only four are absolute --- the blur radius, the floor of 60 ink pixels per emitted line, the $64\times640$ canvas size and the dynamic-programme weights.

Before any threshold can be fixed, the line itself needs a shared vocabulary. Every subsystem from here onwards measures handwriting against five quantities shown in Figure~\ref{fig:seg-geom}: the \emph{baseline}, the \emph{x-height} $x_{\mathrm h}$ (the height of a lower-case letter with no tall part and no tail), an \emph{ascender} and \emph{descender} reaching above and below that, and the \emph{line pitch} $P$, the baseline-to-baseline distance. The pitch $P$ is the unit of this block, because segmentation separates one line from the next; the x-height $x_{\mathrm h}$ is the unit of everything downstream (Sections~\ref{sec:wid-strokenorm}, \ref{sec:styleprofile}, \ref{sec:synthesis}), because measuring in x-heights removes both the camera's distance and the writer's absolute size as variables, so one stored style profile can be drawn at any pen size.

\subsubsection{Array primitives: summed-area tables and run tests}
\label{sec:seg-prims}

Almost every operation in this block is a sum, a maximum, or a test of whether anything is set, taken over a rectangular window. Computed directly, a window of radius $r$ costs $O(r)$ per pixel per axis, too slow here because the illumination blur below uses a radius of up to 40 pixels. The module therefore builds a summed-area table~\cite{crow1984}, also called an integral image, in one $O(HW)$ pass of two cumulative sums, after which the sum over a window of \emph{any} size costs four look-ups instead of $(2r+1)^2$ additions. Three stages of this block resample an image, and each does so by bilinear interpolation at the source position given by Equation~\ref{eq:seg-resize}, the one exception being an ownership map resampled by nearest neighbour, because its values are integer line indices that interpolation would invent new values for:
\begin{equation}
y_s=\frac{(i+0.5)\,h}{h'}-0.5,\quad x_s=\frac{(j+0.5)\,w}{w'}-0.5,\quad I'(i,j)=\sum_{a,b\in\{0,1\}}\omega_{ab}\,I(\lfloor y_s\rfloor+a,\lfloor x_s\rfloor+b).
\label{eq:seg-resize}
\end{equation}

The table itself is the running two-dimensional sum of the image,
\begin{equation}
S(y,x)=\sum_{i<y}\sum_{j<x} I(i,j),
\label{eq:seg-sat}
\end{equation}
where $S$ is the summed-area table and $I$ the image being summed. Equation~\ref{eq:seg-sat} is built once per image. Any window sum is then read from four of its entries,
\begin{equation}
\mathrm{BoxSum}=S(y_2,x_2)-S(y_1,x_2)-S(y_2,x_1)+S(y_1,x_1),
\label{eq:seg-boxsum}
\end{equation}
where $y_2=y_1+2r+1$ and $x_2=x_1+2r+1$ are the far corners of a window of radius $r$, the array having been padded by $r$ with edge replication beforehand. The cost of Equation~\ref{eq:seg-boxsum} does not depend on $r$, which is what makes the radius-40 illumination blur of Section~\ref{sec:seg-binarise} affordable.

The same cumulative trick gives the two binary operations the block needs. A dilation along one axis is
\begin{equation}
\mathrm{AnyWithinRadius}(m,r)[i]=\bigl[\,c[i+2r+1]-c[i]>0\,\bigr]=\Bigl[\textstyle\bigvee_{k=-r}^{r} m[i+k]\Bigr],
\label{eq:seg-dilate}
\end{equation}
where $m$ is the binary mask, $c$ its cumulative sum and $r$ the radius. Equation~\ref{eq:seg-dilate} is a dilation because the bracket is true exactly when at least one pixel within $r$ is set. A square dilation separates into two applications of it, one per axis, so it costs the same at any radius. An erosion is the complemented dilation of the complement, and a closing is a dilation followed by an erosion, so no other structuring element has to be implemented. The second operation marks long runs,
\begin{equation}
\mathrm{LongRun}(m,n)[j]=\bigl[\,\mathrm{ch}[h_j+1]-\mathrm{ch}[l_j]>0\,\bigr],\qquad l_j=\max(0,j-n+1),\quad h_j=\min(j,L-n),
\label{eq:seg-runmask}
\end{equation}
where $n$ is the minimum run length, $\mathrm{ch}$ the cumulative count of positions at which a run of $n$ consecutive set pixels begins, $L$ the length of the axis, and $l_j,h_j$ the first and last such start positions that could cover index $j$. Equation~\ref{eq:seg-runmask} is true at every pixel lying on a run of at least $n$ set pixels, and is used by Section~\ref{sec:seg-cleanup} to find printed rules. Only one true Gaussian filter is used anywhere in the block, a 25-tap kernel smoothing the row profile of Section~\ref{sec:seg-pitch} with $\sigma=4$ rows, about a tenth of a typical pitch.

Algorithm~\ref{alg:seg-prims} states all three primitives. None contains a loop over pixels: each is two cumulative sums and a slice difference, which is why a window of any size costs the same.

\begin{algorithm}[!htbp]
\caption{The three array primitives, each independent of window size}
\label{alg:seg-prims}
\begin{algorithmic}[1]
\STATE \textbf{BoxMean}(image, radius $r$) \COMMENT{mean over a $(2r{+}1)\times(2r{+}1)$ window}
\STATE \quad pad the image by $r$, replicating the edge
\STATE \quad $\mathrm{integral}\leftarrow$ cumulative sum down, then cumulative sum across \COMMENT{Equation~\ref{eq:seg-sat}}
\STATE \quad \textbf{return} (four corner look-ups into $\mathrm{integral}$) $/\,(2r+1)^2$ \COMMENT{Equation~\ref{eq:seg-boxsum}}
\STATE
\STATE \textbf{AnyWithinRadius}(mask, radius $r$, axis) \COMMENT{one-axis dilation, Equation~\ref{eq:seg-dilate}}
\STATE \quad $c\leftarrow$ cumulative sum of the mask along the axis
\STATE \quad \textbf{return} $c[i+2r+1]-c[i]>0$ for every position $i$
\STATE
\STATE \textbf{LongRunMask}(mask, length $n$, axis) \COMMENT{pixels lying on a run of $n$ or more, Equation~\ref{eq:seg-runmask}}
\STATE \quad $c\leftarrow$ cumulative sum of the mask along the axis
\STATE \quad $\mathrm{hit}\leftarrow\bigl(c[i+n]-c[i]=n\bigr)$ \COMMENT{a run of $n$ starts at $i$}
\STATE \quad $\mathrm{ch}\leftarrow$ cumulative sum of $\mathrm{hit}$
\STATE \quad \textbf{return} $\mathrm{ch}[h_j]-\mathrm{ch}[l_j]>0$ \COMMENT{some such run covers $j$}
\end{algorithmic}
\end{algorithm}

\subsubsection{Lighting normalisation and binarisation}
\label{sec:seg-binarise}

The intensity measured by a camera is approximately the reflectance of the paper multiplied by the illumination falling on it. Because the nuisance term is a multiplication and not an addition, it is divided out rather than subtracted: the working grey image $G$ is divided by a single box mean of itself, giving a ratio image $\rho$ close to 1 on paper whatever the lighting, and on ink the ink-to-paper reflectance ratio of the pen itself. Once the shading is divided out, the ink decision is a single global threshold, chosen by Otsu's method~\cite[p.~63]{otsu1979}, which is possible only because of the division --- this is the step that removed the long chain of clean-up filters the project's first segmenter needed.

The ratio image is formed by dividing the grey image by a box mean of itself,
\begin{equation}
\rho(p)=\frac{G(p)}{\max\bigl(\mathrm{BoxMean}_r(G)(p),\,1\bigr)},
\label{eq:seg-flat}
\end{equation}
where $\rho(p)$ is the ratio at pixel $p$, $G$ the working grey image and $\mathrm{BoxMean}_r$ the mean over a window of radius $r$, evaluated through Equation~\ref{eq:seg-boxsum}. The denominator is floored at 1 so a black border cannot divide by zero. The radius is tied to the image height,
\begin{equation}
r=\max\bigl(8,\;\min(40,\;\mathrm{round}(H/41))\bigr),
\label{eq:seg-flatradius}
\end{equation}
where $H$ is the height of the working image in rows. Equation~\ref{eq:seg-flatradius} makes the background estimate cover the same fraction of the page at any camera resolution. The radius must be much larger than a letter, or letters would darken their own background estimate and be divided away; the bounds of 8 and 40 rows keep it so at the resolutions used here.

The threshold separating ink from paper is then the one that best splits the histogram of $\rho$ into two groups, by Otsu's criterion~\cite[p.~63]{otsu1979},
\begin{equation}
t^*=\arg\max_t\;\omega_B(t)\,\omega_F(t)\,\bigl[\mu_B(t)-\mu_F(t)\bigr]^2 ,
\label{eq:seg-otsu}
\end{equation}
where $t^*$ is the chosen threshold, $\omega_B(t)$ and $\omega_F(t)$ are the fractions of pixels below and above a candidate $t$, and $\mu_B(t)$ and $\mu_F(t)$ are their means. The quantity maximised in Equation~\ref{eq:seg-otsu} is the between-class variance, and it is evaluated for all 256 histogram bins at once. A pixel is marked as ink when $\rho<t^*$. Applying Equation~\ref{eq:seg-otsu} globally is defensible only because Equation~\ref{eq:seg-flat} has already removed the shading that would otherwise force a local threshold.

One extra test is needed beyond the threshold: a solid-area veto removes any window entirely ink, since no pen stroke fills a $9\times9$ window, which catches a binder shadow or the dark gutter of a bound book. The whole stage is the four array statements of Algorithm~\ref{alg:seg-ink}, and holds no tunable grey level --- which is the result of dividing the illumination out before thresholding rather than after.

\begin{algorithm}[!htbp]
\caption{Lighting normalisation and the ink mask}
\label{alg:seg-ink}
\begin{algorithmic}[1]
\STATE \textbf{OtsuThreshold}(values) \COMMENT{the cumulative form of Equation~\ref{eq:seg-otsu}, all 256 bins at once}
\STATE \quad $\mathrm{histogram}\leftarrow$ 256 bins of the values clipped to $[0,1.2]$
\STATE \quad $w,m\leftarrow$ cumulative class weight and cumulative class mean
\STATE \quad $\mathrm{variance}\leftarrow(\text{total mean}\cdot w-m)^2/\bigl(w\,(1-w)\bigr)$
\STATE \quad \textbf{return} the bin centre maximising $\mathrm{variance}$
\STATE
\STATE \textbf{InkMask}(grey)
\STATE \quad $r\leftarrow\max\bigl(8,\min(40,\mathrm{round}(H/41))\bigr)$ \COMMENT{Equation~\ref{eq:seg-flatradius}}
\STATE \quad $\mathrm{ratio}\leftarrow \mathrm{grey}/\max(\mathrm{BoxMean}(\mathrm{grey},r),1)$ \COMMENT{divide, not subtract: Equation~\ref{eq:seg-flat}}
\STATE \quad $\mathrm{mask}\leftarrow \mathrm{ratio}<\textbf{OtsuThreshold}(\mathrm{ratio})$
\STATE \quad $\mathrm{solid}\leftarrow \mathrm{BoxMean}(\mathrm{mask},4)>0.999$ \COMMENT{a $9\times9$ window wholly ink}
\STATE \quad \textbf{return} $\mathrm{mask}\wedge\neg(\text{dilate }\mathrm{solid}\text{ by }3)$, and $\mathrm{ratio}$
\end{algorithmic}
\end{algorithm}

The threshold 0.999 rather than 1 absorbs floating-point error in the integral image; the fringe is removed with the blob because a shadow's edge is as unwanted as its interior.

\subsubsection{Deskew by searching rotations}

When text lines are horizontal, the row-sum profile of the ink has sharp peaks at the line bodies and deep troughs between them; any tilt smears those peaks, since a single row then cuts across several lines. This projection-profile approach to skew detection~\cite{postl1986} is a standard alternative to a Hough transform over ink edges~\cite{duda1972}, chosen here because a page of handwriting and printed rules gives the Hough transform many competing line candidates, whereas the row profile already favours the direction most of the ink actually runs in. The sharpness of the profile is therefore a measure of how level the page is, and can be maximised directly.

The row profile at a trial angle is the ink count per row,
\begin{equation}
P_\theta(y)=\sum_x R_\theta(y,x),
\label{eq:seg-profile}
\end{equation}
where $P_\theta(y)$ is the number of ink pixels in row $y$ and $R_\theta$ is the ink mask notionally rotated by $\theta$. The sharpness of Equation~\ref{eq:seg-profile} is scored by its sum of squares, and the angle maximising that score is taken,
\begin{equation}
J(\theta)=\sum_y P_\theta(y)^2,\qquad \theta^*=\arg\max_\theta J(\theta),
\label{eq:seg-skew}
\end{equation}
where $J(\theta)$ is the objective and $\theta^*$ the chosen skew angle. Squaring before summing is what makes Equation~\ref{eq:seg-skew} work: the total amount of ink does not change under rotation, so $\sum_yP_\theta(y)$ is fixed, whereas the sum of squares is largest when the same ink is concentrated into the fewest rows, which happens when the lines are level.

The rotation is never performed to score a candidate. Each ink pixel is mapped straight to the row it would land in,
\begin{equation}
k=(y-c_y)\cos\theta-(x-c_x)\sin\theta+c_y,
\label{eq:seg-skewrow}
\end{equation}
where $k$ is that row index, $(y,x)$ the pixel's coordinates and $(c_y,c_x)$ the image centre. Counting rows through Equation~\ref{eq:seg-skewrow} was measured 31 times faster than rotating the mask seventeen times.

The search sweeps 17 candidate angles from $-4^\circ$ to $+4^\circ$ in steps of $0.5^\circ$ on the stage-2 mask reduced by a further factor of two, with no refinement pass, so the best accuracy reachable is half a step, $0.25^\circ$. Ink that would fall outside the row range at a trial angle is allowed to extend the profile rather than being clipped, since clipping piles out-of-range pixels into one row whose artificial spike scores higher than any real text line; an earlier version with this clipping fault chose an angle four degrees wrong on a tilted page. Only once an angle is chosen is the page itself rotated, bilinearly, and the ink mask and ratio image recomputed, because Equation~\ref{eq:seg-flat} is not rotation-equivariant.

The stage was measured against injected ground truth, and the result closes the loop on Equation~\ref{eq:seg-skew}: seven angles lying on the search grid were recovered \emph{exactly} in 35 of 35 trials, and four angles deliberately placed between grid points were recovered to $0.25^\circ$ --- exactly half the search step --- in 20 of 20 trials (Table~\ref{tab:seg-test}). The objective therefore picks the correct grid point every time, and the residual error is entirely the coarseness of the grid rather than any weakness in Equation~\ref{eq:seg-skew}. Halving the step would halve the residual at twice the cost.

\subsubsection{Line pitch: the scale unit the rest of the block uses}
\label{sec:seg-pitch}
\label{sec:seg-pitchcentres}

Every threshold from here to the end of the block is expressed in multiples of the line pitch $P$, so $P$ must be measured before any of them can be applied. It is obtained from the row-ink profile, the mask pixel count per row over a central window, smoothed by the Gaussian kernel of Section~\ref{sec:seg-prims}:
\begin{equation}
\mathrm{prof}(y)=\sum_{x=\lfloor0.05W\rfloor}^{\lfloor0.97W\rfloor-1}\mathrm{ink}(y,x),\qquad \mathrm{sm}=\mathrm{prof}*k,
\label{eq:seg-pitch}
\end{equation}
where $\mathrm{prof}(y)$ is the ink count in row $y$, $W$ is the image width, $k$ is the 25-tap Gaussian kernel and $\mathrm{sm}$ the smoothed profile. The window in Equation~\ref{eq:seg-pitch} excludes the outer five per cent on the left and three per cent on the right, where a binding shadow or a torn edge would otherwise contribute a constant to every row.

A peak of $\mathrm{sm}$ is a row satisfying three conditions together,
\begin{equation}
\mathrm{sm}(y)\ge\mathrm{sm}(y-1),\qquad \mathrm{sm}(y)>\mathrm{sm}(y+1),\qquad \mathrm{sm}(y)>0.06\max_u\mathrm{sm}(u),
\label{eq:seg-centres}
\end{equation}
where $y$ is a candidate row. The comparisons in Equation~\ref{eq:seg-centres} are deliberately asymmetric, one non-strict and one strict, so the last row of a flat-topped peak is taken exactly once. The relative floor of $0.06$ scales with the amount of ink on the page rather than being an absolute count, so a faint page is not rejected wholesale.

The pitch is the \emph{median} of the gaps between consecutive peaks, used whenever at least two peaks exist; a median rather than a mean so one unusually large gap, such as a paragraph break, cannot shift it. Three fallbacks follow in order when fewer than two peaks are found, so the stage degrades rather than failing (Algorithm~\ref{alg:seg-pitch}). Measured over the 30 photographed pages, $P$ ranged from 47 to 58 pixels --- a 23\,\% spread across five writers at one camera distance, which is the variation goal~1 of Section~3.4.1 exists to absorb and the reason no threshold in this block is an absolute pixel count.

\begin{algorithm}[!htbp]
\caption{Measuring the line pitch, with three fallbacks}
\label{alg:seg-pitch}
\begin{algorithmic}[1]
\STATE $\mathrm{profile}\leftarrow$ ink pixels per row, over the central 5\,\% to 97\,\% of the width \COMMENT{Equation~\ref{eq:seg-pitch}}
\STATE $\mathrm{smoothed}\leftarrow \mathrm{profile}$ convolved with a 25-tap Gaussian, $\sigma=4$ rows
\STATE $\mathrm{peaks}\leftarrow$ interior rows satisfying all three tests of Equation~\ref{eq:seg-centres}
\IF{at least two peaks}
    \STATE \textbf{return} the median gap between consecutive peaks \COMMENT{the normal path}
\ELSE
    \STATE autocorrelate the mean-removed profile; take the first lag in $15\ldots\min(200,L/3)$ reaching $0.7$ of the segment maximum
\ENDIF
\IF{no such lag}
    \STATE $P\leftarrow\max\bigl(15,\ \mathrm{round}(2.2\cdot\text{median letter height})\bigr)$
\ENDIF
\IF{no usable components either}
    \STATE $P\leftarrow48$ rows \COMMENT{last resort; never reached on the 30 pages tested}
\ENDIF
\end{algorithmic}
\end{algorithm}

The autocorrelation is a fallback only, and deliberately so: it can lock onto a multiple of the true spacing, which would halve the line count without any other symptom. The smoothed profile is returned alongside $P$ and reused for the line centres of Section~\ref{sec:seg-centres}, so the scale unit and the line positions cost one pass over the mask between them.

\subsubsection{Removing what is not handwriting}
\label{sec:seg-cleanup}

Three kinds of nuisance are removed in turn, each identified by a property that handwriting does not share. The area outside the sheet is removed because handwriting disappears under a coarse enough average while the sheet itself does not. Printed structure --- ruled paper, underlines, a bound book's spine shadow --- is removed because it runs straight for longer than a line spacing, which handwriting does not, a long directional opening rather than a fixed-size filter. Edge slivers, corner shadows and creases are removed because, although not straight, they are judged as whole connected pieces rather than pixel by pixel: each fragment is labelled by the same connected-component logic used throughout this block, and the whole piece is then scored on being long and thin or sparse inside its own bounding box.

The long-run primitive of Equation~\ref{eq:seg-runmask}, bracketed by a dilation and a re-intersection with the real ink, gives Equation~\ref{eq:seg-cand} for flat (horizontal) and upright (vertical) printed structure, where $\mathcal D_r^{y}$ and $\mathcal D_r^{x}$ are one-axis dilations:
\begin{equation}
\begin{aligned}
\mathrm{flat}&=\mathcal D_{1}^{y}\Bigl(\mathrm{LongRun}^{x}\bigl(\mathcal D_{1}^{y}(\mathrm{ink}),\;\lfloor1.25P\rfloor\bigr)\Bigr)\wedge\mathrm{ink},\\
\mathrm{upright}&=\mathcal D_{3}^{x}\Bigl(\mathrm{LongRun}^{y}\bigl(\mathcal D_{3}^{x}(\mathrm{ink}),\;\lfloor1.4P\rfloor\bigr)\Bigr)\wedge\mathrm{ink}.
\end{aligned}
\label{eq:seg-cand}
\end{equation}
The two run lengths, $1.25P$ horizontally and $1.4P$ vertically, are longer than any single letter can be, so no letter is mistaken for a rule; the dilation before the run test tolerates a slight tilt, and the re-intersection means only real ink is ever removed. Both are stated as multiples of the $P$ measured in Section~\ref{sec:seg-pitch}, which is why that stage has to come first.

Separating ink into pieces for the third kind of nuisance needs connected-component labelling: every set pixel is given an integer label, two pixels sharing a label when a path of set pixels joins them. The mask is closed first so pen lifts inside a word are bridged, and the labelling is a run-length union-find pass, each row reduced to its horizontal runs before a union-find structure records which runs belong together, so the whole page is labelled in one pass over the rows. Every discard statistic is accumulated over the \emph{original} ink pixels, not the closed mask, so closing can join pieces but never add area to a decision.

Each closed piece is then judged as a whole and discarded if any one of the eight predicates of Table~\ref{tab:seg-artifact} holds, for a piece of area $A$, height $h$ and width $w$, with $e=\max(3,\lfloor0.5P\rfloor)$ counting as touching the frame, $x_L$ the fifth percentile of the left edges of the letter-like pieces ($A\ge0.065P^2$, $h\le2.2P$) and faintness defined as $\bar\rho_c>0.85\,t^*$, relative to the page's own threshold so that one constant serves pencil and fibre tip.

\subsubsection{Line centres on the cleaned mask}
\label{sec:seg-centres}

The pitch of Section~\ref{sec:seg-pitch} was measured on the raw ink mask, because the clean-up of Section~\ref{sec:seg-cleanup} needed it. Now that the nuisances are gone, the profile and the pitch are \emph{recomputed} on the cleaned mask by the same Equation~\ref{eq:seg-pitch}, and the peaks of Equation~\ref{eq:seg-centres} become the line centres. Recomputing matters because a printed rule contributes a full-width row of ink, which is the strongest peak a profile can have; measuring the centres before clean-up on ruled paper would place a line on every rule.

The peaks are reduced to centres by greedy non-maximum suppression: a peak is accepted only if it lies at least $0.6P$ from every centre already accepted. The separation is more than half a pitch, so two genuine lines can never be merged into one.

\subsubsection{Seam cut, pixel ownership and the final crop}

A straight cut halfway between two line centres would sever every descender and ascender that crosses it, so the boundary between two lines must bend around the ink. The two layers of ink recovery --- a strict page-wide mask and a looser threshold trusted only next to ink a line already owns --- exist because a threshold loose enough to catch a faint stroke is also loose enough to catch a shadow, and \emph{hysteresis}, using two thresholds instead of one, is the standard remedy, the same principle used to link edges in edge detection applied here to ink.

The boundary itself is found the way a seam is found in content-aware image resizing: the cheapest vertical path across a cost image, found column by column with dynamic programming rather than guessed as a straight line~\cite[p.~10:3]{avidan2007}. Between consecutive centres $c_0<c_1$ the cost field of Equation~\ref{eq:seg-cost2} and the dynamic-programme recursion of Equation~\ref{eq:seg-seam} give the cheapest path across it:
\begin{equation}
C(y,x)=4.0\,\tilde m(y,x)+0.012\left(\frac{y-\mu}{\max(1,(c_1-c_0)/2)}\right)^{\!2},\qquad \mu=c_0+\tfrac12(c_1-c_0),
\label{eq:seg-cost2}
\end{equation}
where $C(y,x)$ is the cost of placing the boundary at row $y$ of column $x$, $\tilde m$ is the dilated ink mask, and $\mu$ is the midline between the two centres $c_0$ and $c_1$. The two weights in Equation~\ref{eq:seg-cost2} are three hundred to one: crossing a single ink pixel costs 4.0 against a maximum of 0.012 for sitting a half-gap away from the midline, so the midline term only breaks ties across blank gaps between words and never persuades the seam to cut a letter.

The cheapest path is accumulated column by column,
\begin{equation}
A(y,x)=C(y,x)+\min_{|d|\le s}\bigl[\,A(y+d,\,x-1)+0.02\,|d|\,\bigr],\qquad A(y,0)=C(y,0),
\label{eq:seg-seam}
\end{equation}
where $A(y,x)$ is the cost of the cheapest path reaching $(y,x)$, $d$ is the row step taken between adjacent columns and $s=7$ bounds it. The penalty $0.02\,|d|$ in Equation~\ref{eq:seg-seam} prices vertical movement, so the seam prefers to stay level unless ink gives it a reason to climb. Algorithm~\ref{alg:seg-seam} states the minimisation, which is exact: a path cost is a sum over columns, and every admissible predecessor is considered.

\begin{algorithm}[!htbp]
\caption{The least-ink seam between two line centres}
\label{alg:seg-seam}
\begin{algorithmic}[1]
\REQUIRE consecutive line centres $c_0<c_1$, step bound $s=7$
\STATE $\mathrm{cost}\leftarrow 4.0\cdot\mathrm{closedInk}+0.012\bigl((\mathrm{row}-\mu)/\mathrm{halfGap}\bigr)^2$ \COMMENT{Equation~\ref{eq:seg-cost2}}
\STATE $\mathrm{acc}[:,1]\leftarrow \mathrm{cost}[:,1]$
\FOR{$x=2$ \TO $W$}
    \FOR{each displacement $d\in-s\ldots+s$}
        \STATE $\mathrm{candidate}[d]\leftarrow \mathrm{acc}[\mathrm{row}+d,\;x-1]+0.02\,|d|$
    \ENDFOR
    \STATE $\mathrm{acc}[:,x]\leftarrow \mathrm{cost}[:,x]+\min_d \mathrm{candidate}[d]$ \COMMENT{Equation~\ref{eq:seg-seam}}
    \STATE $\mathrm{back}[:,x]\leftarrow$ the $d$ that achieved the minimum
\ENDFOR
\STATE backtrack from the cheapest entry of the last column
\end{algorithmic}
\end{algorithm}

All rows of a column are evaluated at once as $2s+1$ shifted candidate arrays, so only the displacements and the backtrack are loops. The two outermost boundaries are fixed at $\lfloor0.75P\rfloor$ beyond the first and last centre, so $L$ centres give exactly $L$ bands; the whole computation is $O(15HW)$ at worst, the most expensive single step in the block.

A pixel belongs by default to the band it lies in. Six correction rules are then applied on top of that default, each of which may move a piece to an adjacent band or drop it but never further. They rest on each band's share of a piece's ink, with $0.15$ counting as a genuine presence, and on the \emph{major} band, defined as the topmost band reaching the piece, since a piece spanning two lines is the upper one's descender.

Each crop is rendered from the full-resolution page and composited from three layers: the band's own ink mask, a recovery mask from re-applying Equations~\ref{eq:seg-flat} and~\ref{eq:seg-otsu} inside the crop alone, and the halo of the band's own strong ink. The three are combined by the hysteresis rule
\begin{equation}
\alpha=\max\Bigl(\alpha_{\mathrm{strong}},\ \ \mathbb 1[\rho_{\mathrm{local}}<t^*_{\mathrm{local}}]\cdot\alpha_{\mathrm{halo}}\cdot\mathbb 1[\text{not owned by another band}]\Bigr),
\label{eq:seg-hyst}
\end{equation}
where $\alpha$ is the opacity written into the crop, $\alpha_{\mathrm{strong}}$ comes from the page-wide mask, $\alpha_{\mathrm{halo}}$ from the looser local threshold $t^*_{\mathrm{local}}$, and $\mathbb 1[\cdot]$ is 1 when its condition holds and 0 otherwise. The second term of Equation~\ref{eq:seg-hyst} is the loose layer, admitted only next to ink the band already owns, which is the hysteresis: a faint stroke touching known ink is kept, while an equally faint shadow elsewhere is not.

Finally the crop's contrast is stretched,
\begin{equation}
\ell=\mathrm{clip}\!\left(\frac{255\,(v-b)}{\max(w-b,1)},0,255\right),\qquad
\mathrm{out}=255\Bigl(1-\bigl(\tfrac{255-\ell}{255}\bigr)^{0.55}\Bigr),
\label{eq:seg-stretch}
\end{equation}
where $v$ is the input grey value, $b$ and $w$ are the black and white points taken from the crop's own histogram, $\ell$ is the linearly stretched value and $\mathrm{out}$ the value written. The exponent $0.55$ in Equation~\ref{eq:seg-stretch} thickens thin strokes slightly, which matters because the recogniser was trained on ink of a similar weight. Outside the mask the crop is pure white, and it is shifted so the first inked column sits at a fixed offset, since the recogniser's input is left-flush (Equation~\ref{eq:seg-clf}):
\begin{equation}
s=\min\!\Bigl(\frac{64}{h},\frac{640}{w}\Bigr),\qquad h'=\max(1,\mathrm{round}(hs)),\qquad w'=\max(1,\mathrm{round}(ws)).\label{eq:seg-clf}
\end{equation}

\subsubsection{Design alternatives and limitations}

Table~\ref{tab:seg-alt} sets the main design choices against the alternatives considered. The project's first segmenter, \texttt{SegmentPage.py}, was about 2200 lines and sixty functions against the eleven here; it resized every photograph to a fixed long side, thresholded locally, removed printed structure in four passes, took a median glyph height as its scale unit, scored components for being diagrams, chained them into lines and deskewed each line separately. No part of the deployed pipeline calls it any more, and three of its capabilities were given up with it: diagram tagging, per-line deskew, and a wider $\pm8^\circ$ search at $0.1^\circ$. The replacement is about a quarter of the size and roughly five times faster, at the cost of those three capabilities.

The block assumes left-to-right writing in a single column of roughly horizontal lines, and the following limitations follow from that design. Skew beyond $\pm4^\circ$ is not corrected at all, and up to $0.25^\circ$ always remains. Two columns of text, or a diagram beside the text, produce profile peaks that belong to no single line, and an untagged diagram is cut into line-shaped crops and read as nonsense. A line peaking below six per cent of the strongest is lost silently, although no such line occurred in the 30 pages tested. A blank page raises an exception rather than returning no lines. Illumination varying faster than the radius of Equation~\ref{eq:seg-flat} leaves one side of a hard shadow edge mis-thresholded, page curl and perspective are untreated, and colour is treated like black ink because the module is monochrome throughout.
