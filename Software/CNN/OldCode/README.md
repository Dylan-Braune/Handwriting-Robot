# Handwriting Robot — CNN / CRNN pipeline

## What to run for an overnight (~8h+) training session

From this directory (`Software/CNN`):

```bash
python train_handwriting_robot_v1_baseline.py --epochs 400 --batch-size 16 --eval-every 2 --checkpoint-every 1 --target-char-acc 0.95 --target-patience 3 --held-out-last-page --resume > logs/train_v1_baseline_run1.log 2>&1
```

That's it — data-dir defaults to `Data/Datasets/IAMpages671`, which is already fully verified (see "Dataset status" below).

- It auto-stops early once held-out character accuracy hits 95% for 3 evals in a row, so it won't necessarily run the full 400 epochs.
- Safe to `Ctrl+C` and resume later: rerun the exact same command (the `--resume` flag picks up from `weights/train_handwriting_robot_v1_baseline_checkpoint.pth`).
- If it has a CUDA GPU available it'll use it automatically; otherwise CPU.
- First few minutes are just it loading and cropping all 1,414 pages into memory — normal, not stuck.
- Progress lines look like: `Epoch 042/400 | loss ... | val char-acc 0.xxxx | val CER 0.xxxx | val exact-line 0.xxx | val author-acc 0.xxx`

## Dataset status

`Data/Datasets/IAMpages671/data/` is fully generated and verified as of this session:

To regenerate from scratch if ever needed: `python generate_all_labels.py`.

## Folder layout

**Active pipeline:**
- `FullLineBoxMaker.py` — core page → line-crop segmentation + printed-header OCR (shared by everything below)
- `generate_all_labels.py` — (re)generates `_labels.txt` for every page in `Data/Datasets/IAMpages671`
- `generate_labels_iampages10.py` — same, but for the small 10-author validation set in `Data/Datasets/IAMpages10`
- `verify_all_authors.py` — sanity-checks that detected line-boxes match label line-counts, for every author
- `generate_spot_check_previews.py` — dumps bounding-box preview images (every ~20th author) for visual spot-checking
- `train_handwriting_robot_v1_baseline.py` — the training script (see below for versioning)
- `recognize_line_crnn.py` — run a trained model on a single page image

**`weights/`** — every training run's output lives here, named after the script that produced it (e.g. `train_handwriting_robot_v1_baseline_weights.pth` / `_checkpoint.pth`). Nothing here ever gets silently overwritten by a *different* version.

**`logs/`** — training/generation logs from past runs.

**`handwriting_line_extraction_output/`** — reports and preview images generated by the scripts above (label-generation report, line-box verification report, spot-check previews).

**`archive/`** — earlier exploratory scripts and old weight files from before this session's rework (`AutoTranscriber.py`, `boundingBoxMaker.py`, etc.), kept for history but superseded by the pipeline above.

## Versioning convention

Each new implementation idea (e.g. adding deskewing, a residual CNN backbone) gets its own new file — `train_handwriting_robot_v2_<short-description>.py` — rather than editing `_v1_baseline.py` in place. Because each script's `run_name` is derived from its own filename, its weights automatically land in `weights/` under a matching name, so every version's results are kept side by side for comparison. Nothing needs to be passed manually to get this — just copy, modify, rename, run.
