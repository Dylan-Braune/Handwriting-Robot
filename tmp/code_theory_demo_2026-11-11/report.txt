                                                  Handwriting robot




The need for handwriting still exists for authenticity, ease of communication and personal touches. The problem is that
many individuals do not possess the time, skills or ability to write neatly and legibly. This leads to the solution presented
in this proposal: a handwriting robot capable of recognizing a user's handwriting style and being able to replicate it.

The proposed solution is a handwriting robot capable of training on multiple different user's handwritten text (using a
page-scanning rig to capture the handwritten page like the one seen in the image) and being able to produce any desired
piece of text in any of these user's writing styles (using a text reproduction rig like the one seen in the image). The system
will be able to recognize which user authored a piece of text and identify what text was written (shown to the user
through a display as seen in the image). A gantry with 2-dimensional movement will perform actions with a pen to
automatically reproduce the desired text.
1. Text image processing will be performed from first principles, including the isolation of letters from an image of various fonts and sizes of handwritten text.
2. A neural network will be designed and trained from first principles to be able to categorize text to different user's styles based on certain style elements, and identify the text written.
3. A gantry rig will be designed to be capable of performing the necessary precise 2-dimensional movements using a pen, whilst holding the pen and paper securely in place.
4. Pen path planning will be implemented, which involves the conversion of written characters to a 2D motion the gantry needs to perform, and then mapping the movement to stepper
motor controls.



1. Image processing and deep learning will be performed on a single board computer (instead of on a personal computer), which has limited memory, storage and power.
2. Smooth motor control will be needed to produce precise and consistent pen movement to create accurate text.
3. Near real-time classification of handwritten text and reproduction of digital text on paper will need to be achieved.




There are three main modes of operation for the handwriting robot: training, classification and reproduction
Training/Classification: First, the user will input their page of handwritten text to the scanner (FU 1.1). The user will select to either train or classify, and will input the intended digital
text alongside this through an input interface. Once the page is scanned, a camera USB driver will be used to transfer the image to the single board computer (FU 1.2). The image will
be conditioned first to fix warping or noise in the image (FU 2.1), and then the character separation will occur. This will separate the page characters (or groups of characters that are
connected) to match the desired neural network input size (FU 2.2). The difference between training and classification occurs here: if the 'training' option is selected, the separated
characters will be used to adjust the neural network neuron weightings against the desired digital text that was input (FU 2.4). Each separated character or group of characters will also
be converted into a trajectory map (coordinate map of required pen motion) (FU 2.5). This trajectory map will be stored permanently within the system (FU 2.6). If the 'classify' option
is selected, the separated characters or group of characters will be passed into the trained neural network classifier (FU 2.3), and the corresponding digital text and detected user will be
outputted to the display interface.

Reproduction: If the user sends a 'write' instruction, the digital text and user style desired to be reproduced will be provided. The corresponding trajectory for each character/group will
be retrieved from storage (FU 2.7), and will be converted into stepper motor controls required to produce the desired pen movements (FU 2.8). These stepper motor controls will be
sent to the corresponding motors via a stepper motor driver to allow for forward and reverse movements (FU 3.1). The x-motor, y-motor and pen lift mechanism will be controlled
through the stepper motor driver (FU 3.2/3.4). After the pen has been adjusted and is held securely by the pen holder in the robot (FU 3.3), precise handwritten imitations of each
character will be written.

1. Literature study



1.1     Handwriting recognition and writer identification


1.1.1   Offline recognition and available datasets
The ability of a computer or system to identify written text after being trained on large amounts
of data is known as HWR (Handwriting Recognition) or HTR (Handwritten Text Recognition) [1,
p. 39]. One type of handwritten text recognition is offline recognition, which means the data
being identified by the system is static and captured post-completion of the page of handwritten
text. This is ideal for identifying the text from a fixed image of handwritten content by utilising
image processing techniques and algorithms to identify the text that was written [2, p. 268]. The
other type is online recognition, which is a more dynamic process that uses information recorded
during the creation of the handwriting. The addition of a time variable includes data about the
order of strokes as well as pen-up or pen-down movements [3, p. 18].
This project uses offline recognition because its inputs are photographed or scanned pages. The
text and writer must therefore be identified from visible ink geometry. The absence of recorded
stroke order also influences how the handwriting can later be reproduced: a path recovered from
an image is a geometric estimate, rather than a recording of the writer’s movements.
Multiple datasets have been used for training handwritten text recognition modules. The EMNIST
(Extended MNIST) By_Class dataset consists of 814 255 handwritten characters and numbers,
each being 28 by 28 pixels in size [1, p. 40]. There is only a single character per image,
which suits isolated-character classification but does not itself supply examples of connected
handwritten words. The IAM handwriting dataset provides complete handwritten English pages,
lines and words with their transcriptions and writer metadata [4]. Hemanth et al. report the
expanded database as 5 685 labelled sentences and 115 320 labelled words from 657 writers [5,
p. 2460].
The dataset influences which variations the classifier encounters and which labels are available.
For this project, line images and their transcripts support recognition without manually labelling
every character boundary. Writer-labelled pages also support author classification and extraction
of individual style profiles. IAM supplies public handwriting variation, while the personal dataset
represents the project’s photographed input conditions. A small isolated-character dataset alone
would not address both requirements.



1.1.2   Image conditioning and text separation
The image conditioning of handwriting pages includes techniques performed on the handwritten
text before it is passed into the classification and feature-recognition algorithms. This accounts for
dimensional adjustments, removal of inconsistencies and normalisation of the data, to make the
images more appropriate for text separation and classification [5, pp. 2458–2460]. Normalisation
reduces the influence of unwanted variation; examples include min–max scaling and z-score
normalisation [1, pp. 40–41].

Binarisation differentiates the background page from the ink of the written text, computed
by pixel. A global threshold taken from the grey-level histogram uses one decision level for
the image [6]. A local threshold instead uses statistics from a window around each pixel and
can accommodate uneven illumination [7, pp. 2–3]. Deskewing corrects page rotation, while
deslanting corrects the lean of individual characters by applying a horizontal shear. These are
different transformations: aligning text lines does not require removing the writer’s characteristic
slant [8, 9].
For the camera input in this project, illumination correction and deskewing are needed before
the ink is separated into lines. Slant must remain available as a writer-specific measurement; it
can be removed for glyph storage and reapplied when the text is synthesised. The purpose is to
suppress capture variation while retaining the information needed for reproduction.
Text separation is the process of breaking up a page of handwritten text into smaller segments or
blocks that can be used in feature extraction and neural-network classifiers. Existing methods
separate text into lines, words or individual characters. Hemanth et al. obtain lines and words
through filtering, dilation and bounding boxes [5, pp. 2459–2460]. When lines are mostly
straight and separated by blank rows, boundaries can be found from minima in the row ink
profile. Where ascenders and descenders overlap, a boundary that bends between lines is more
suitable. Minimum-cost seam methods provide a way to trace such curved boundaries [10, p. 3].
The project therefore separates whole lines before recognition. This avoids requiring a reliable
cut between every pair of connected letters. Character boundaries are still needed to construct a
glyph library, but there the known transcript and a trained line reader can constrain the extraction.
Line segmentation and glyph extraction consequently solve different problems, even though both
divide an image.



1.1.3   Neural networks and feature extraction
Many different types of neural-network models have been implemented for handwriting recog-
nition, including artificial neural networks (ANNs), convolutional neural networks (CNNs),
recurrent neural networks (RNNs) and combinations of them. ANNs consist of interconnected
neurons, weights, hidden layers and biases that learn a mapping from the input to an output.
CNNs use local connections and shared kernels to extract spatial patterns with fewer independent
parameters than an otherwise comparable fully connected image layer [11, pp. 6–8]. RNNs
maintain a state across a sequence, allowing a prediction to depend on neighbouring evidence [2,
p. 269].
The convolutional layers of a CNN perform feature extraction by sliding a convolutional kernel
over the image. Each local input value is multiplied by a corresponding kernel value, the products
are summed, and a bias and activation function produce an output feature value. Reusing the
kernel allows the same pattern to be detected at different locations [11, p. 6]. For unit stride
and no padding, an N by N input with an f by f kernel returns an (N − f + 1) by (N − f + 1)
feature map. Pooling then reduces spatial resolution and retains selected responses [11, pp. 6–7].
Figure 1 illustrates these operations.

A combination of CNNs and recurrent layers allows an entire line to be read without word or
character separation. The convolutional layers convert the cropped line into feature columns,
and a bidirectional recurrent layer reads the sequence in both directions, providing context from
before and after each position [12, pp. 4–5]. In this offline setting, the sequence axis is the
horizontal position in the image, rather than the measured time at which a pen moved. The full
line crop is available before classification. Related convolutional–recurrent recognition systems
use the same distinction between image features and sequence prediction [13, pp. 2–3].
Long sequences make simple recurrent networks difficult to train because gradients can diminish
or grow through repeated updates. Long short-term memory (LSTM) uses an additive memory
state and gates to control what is retained, replaced and exposed [3, pp. 4–5]. The convolutional

unknown. Connectionist temporal classification (CTC) adds a blank symbol and sums the
probabilities of the paths consistent with the transcript. Repeated adjacent symbols are collapsed

1.1.4   Training and assessment
The way networks are trained corresponds to the architecture they are built from. Batch normal-
isation subtracts the batch mean and divides by the standard deviation, with a stabilising constant
and learned scale and offset [15, p. 4]. Dropout reduces overfitting by removing a random subset
of a layer’s outputs during training, limiting dependence on individual features [16, pp. 1931,
1934]. Data augmentation introduces small rotations, shears or smooth distortions while retaining
the transcription [17]. These methods address different sources of variation and do not replace
separate validation data.
Recognition is commonly assessed through character error rate (CER) or word error rate (WER),
using insertions, deletions and substitutions relative to a reference transcript [14, p. 2]. An
error in one character can spoil a whole word, but word edit error is not simply a count of
words at matching positions. The metric and its reference population must remain explicit when
comparing systems.
For this project, numerical forward passes, backward passes and optimiser updates make the
learning calculations inspectable. A corresponding library implementation supports training
and comparison, with stored arrays used for NumPy inference on the ODROID. The report
distinguishes the selected library-trained weights from the independently trained numerical
models. Character edits, writer decisions and physical drawing measurements are evaluated
separately because they measure different functions.



1.1.5   Techniques for writer identification
There are multiple approaches to identifying the author of a written piece of text. One uses
measured, text-independent features such as slant, height, stroke width, spacing and connectivity.
Another describes the distribution of edge directions and recurring letter fragments, giving a
texture and shape description of the writing [18, p. 701]. Alternatively, a neural network learns
discriminative features from examples labelled by writer [19]. Such a classifier identifies a writer
among its trained classes; it does not automatically identify an unfamiliar person.
This project needs an author classifier to select and assess the stored writer styles, while explicit
geometry measurements are needed to reconstruct their appearance. Ink-trace width can itself
contain writer information [20, p. 162], but the gantry uses its own pen. Stroke normalisation is
therefore applied to reduce reliance on that cue and direct the classifier towards shape. Writer
identity and stylistic fidelity remain separate measures: recognising an author does not establish
that every letter or spacing feature has been reproduced accurately.



1.2     Handwriting synthesis in a writer’s style
Before handwritten text can be reproduced through hardware, the desired text must be created in
the selected author’s style. Four approaches illustrate the trade-offs between source data, learned
variation and the form of the output.

                                                                                                        4
D.R. Braune                                                                             Literature study



Recurrent stroke-level synthesis. A recurrent neural network predicts the next pen movement
through small coordinate offsets and an end-of-stroke indicator. It models a distribution of
possible movements because no letter is written identically every time [3, pp. 18–20]. Its output
is naturally suited to a plotter, but training uses online recordings. This project’s offline pages
contain no measured stroke order, so this approach would require a different source dataset and
an additional generative model.
Adversarial image synthesis. A generative adversarial network trains a generator and discrimin-
ator together: one generates handwriting, while the other helps distinguish generated samples
from real examples. GANwriting also constrains content and writer style to produce text im-
ages [21, pp. 3–7]. Once trained, the generator produces an image in a forward pass. This is a
relevant alternative for learning contextual letterforms, but a raster output still needs conversion
into the pen paths required by this project.
Diffusion-based synthesis. This method learns to reverse a noise-corruption process and gener-
ates handwriting through successive denoising steps. One-DM uses one reference style image
at generation time, while its training uses a much larger handwriting corpus [22, pp. 3–5, 9].
A small reference requirement must therefore be distinguished from the data and computation
required to train the model. For this project, diffusion would add both a separate training task
and image-to-path recovery, rather than directly supplying the motion representation.
Glyph-library synthesis. This method assembles words from shapes or glyphs extracted from
existing handwritten pages. Haines et al. store labelled forms and select and join them using
information about their shape, context and spacing [23, pp. 4–8]. Their standard data collection
uses approximately four A4 pages per writer [23, p. 4]. This suits the project’s small personal
collections and allows explicit control of size, slant and spacing. The main limitation is that
a finite collection of character shapes and joining rules only approximates the way connected
handwriting changes with its neighbours.
Generated handwriting can be assessed through geometric comparisons, recognition and human
judgement. Haines et al. include human evaluation, while image-generation work also uses text
and writer recognition to assess the output [23, pp. 12–14], [21, pp. 8–9]. For the present robot,
model scores help choose a candidate before drawing, but final physical output also needs its
own read-back and geometric assessment. A classifier used to select the candidate is not an
independent human judgement of its style.



1.3    Physical reproduction and pen-path mapping
There are three relevant families of mechanism for reproducing text on paper: Cartesian systems,
serial-chain robots and parallel-chain robots. A Cartesian system consists of a gantry with
independent x–y movement. Serial-chain robots consist of linkages connected in a chain, like
a typical robot arm. Parallel mechanisms use several linked chains to support the moving
platform [24, pp. 5–8]. These arrangements differ in their workspace, mechanical structure and
coordinate transformations.
A Cartesian gantry is suitable here because the page is flat and the main motion requirement
is two-dimensional. Each axis can be commanded and calibrated separately, with a further
pen-lift mechanism for travel. This makes the conversion from an image-derived path to physical



                                                                                                       5
D.R. Braune                                                                            Literature study



coordinates direct, while leaving frame alignment, transmission compliance and missed steps as
practical accuracy concerns.
A pen path is stored as a list of points, and a recovered stroke usually has more points than a
plotter needs. Polyline simplification reduces this list while retaining the stroke’s shape. The
Douglas–Peucker method joins the endpoints, finds the point furthest from that line and retains it
when its distance exceeds a chosen tolerance, then repeats on the resulting parts [25]. A small
tolerance follows the stroke closely; a large tolerance removes more points but can cut corners.
When handwriting exists only as an image, the path must first be recovered, for example by
thinning the ink to a centreline [26, p. 237].
These operations are needed to turn the project’s stored glyphs into manageable G-code trajector-
ies. Simplification controls geometric detail, while the thinning and tracing determine which
strokes are available to the synthesiser. Neither recovers the original writing speed or pressure
from a photograph, so the controller must define its own drawing feed and pen transitions.
There are multiple methods of linear actuation that could be considered for a Cartesian plotting
system, including belt drives, rack-and-pinion drives and screw drives [27]. The project uses
timing belts and pulleys to convert motor rotation into movement along supported rails. This
choice prioritises a straightforward, affordable page-sized mechanism with sufficient travel speed;
its nominal step resolution must still be distinguished from measured positioning accuracy.



1.4    Application of the literature
The literature supports a system built around offline pages, complete-line recognition and explicit
glyph geometry. Image conditioning and curved line separation prepare photographed input;
convolutional features support separate text and writer outputs; transcript-guided extraction
turns observed handwriting into reusable paths. A glyph library then supplies controllable
geometry without training an additional handwriting generator. The Cartesian gantry provides
the physical output stage. Section 2 explains how these choices were combined and developed,
while Section 3 gives their calculations, implementation and verification.

2. Approach

The project was approached as two interacting systems: one interprets photographed handwriting
and constructs writer-specific paths, while the other converts those paths into physical pen
movement. The proposal’s functional analysis provides their responsibilities; the G-code interface
allows their implementation and verification to proceed separately.



2.1    Mechanical Hardware Design
Before any computer vision or neural networks were worked on, the hardware to perform the pen
plotting was created. This is because the hardware does not rely on any of the coding elements to
be complete to be able to be tested, and hardware can experience major delays in production due
to order delays, stock shortages or component failure, adding to the reason for it to be constructed
first. A Cartesian gantry with two independent axes was chosen over some sort of robotic writing
arm, as system requiring only flat, cartesian movement does not need joint-dependent kinematics,
and each axis can be calibrated separately and work indepedently from one another. To achieve
the linear motion required, GT2 timing belts and pulleys were chosen over a lead-screws due to
their lower cost, faster travel and ease of customizstion.
Two NEMA 17 stepper motors were chosen for the X and Y axes, driven by A4988 driver chips.
Because a stepper motor always rotates by precisely the number of commanded steps at exact
intervals, accuracy could be assured without an encoder. To allow for even more increased
accuracy and minimal friction, linear bearings were used within the mechanics of the system to
allow parts to move with ease and precision, instead of just having the printed supports sliding
over the steel rails of the gantry. The use of microswitches on the axes allowed the system
to be able to calibrate to reproduce text more accurately. The gantry was designed to be able
to reproduce any G-code file that was provided, allowing for easy integration with the other
subsystems in future.



2.2    Page condition and line segmentation
In parallel while working on the gantry and waiting for hardware to be delivered, work was done
on the first processing stage of the software pipeline, which was performing image conditioning
and segmentation of those pages into a format the future classifiers would accept. A photograph
produces a wide range of inconsistencies that need to be dealt with, including uneven lighting,
page rotation, printed rules, and strokes from neighbouring lines merging into each other. The
image conditioning part of the code was designed to remove these undesired page inconsistencies
without ruining the quality of the original writing, using methods like lighting normalization, ink
separation, and skew correction.
Segmentation of the page of text was chosen to be done lines at a time instead of per word or
character, as it was found that dynamic word separation that worked in all cases was difficult,
and line separation has the added advantage of more context to train and classify text. The design
chosen to perform the segmentation involves locating line centres first, finds curved boundaries
between the lines and its ascenders and descenders, and only then uses the geometry of each
ink piece to decide which line actually owns it. Deskewing, removal of image background,
and artefact rejection were deliberately ordered to run before line centres are estimated, while

                                                                                                       7
D.R. Braune                                                                                   Approach



recovery of faint ink was left until after ownership of each piece had already been decided, since
doing it earlier risked reattaching noise to the wrong line. The system fomatted each page into
the ideal crop sizes to be passed into the text and author classifiers.



2.3    Text and writer classification
Once clean line crops were available, the next stage had two jobs: reading the text and identifying
who wrote it. Both depend on the same stroke features, so a single convolutional backbone was
built, but then the writer and author classifiers varied after that point. The text classifier uses a
CNN–BiLSTM architecture with decoded CTC output, which was heavily based off existing
research, and chosen because it reads a whole line without needing individual characters pre-cut,
as mentioned in the segmentation section, and cursive text has no reliable character boundary to
cut at in the first place.
Training data came from a mix of public handwriting (IAM) and the project’s own photographed
pages, and both author and text models were trained using hold-out pages or lines to allow the
system to be validated against, to prove over-fitting did not occur. The writer network’s input was
stroke-normalised rather than using varying ink thickness from real pages, specifically because
the gantry’s own pen produces constant stroke thicknesses, regardless of the author.



2.4    Style extraction and handwriting reproduction
Once the previous subsystems were created, the actual text synthesis and reproduction was
made. Four reproduction methods were considered, and the method chosen instead was a stored
set of normalised glyph trajectories. The other were not chosen because an online dataset of
pen strokes was not available, and the chosen IAM dataset was not extensive enough to train a
rpeproduction model, neither was the necessary GPU processing power available for it. Using
the glyph trajectory method simply resused data and models the project already had, but at the
cost of weaker handling of how letters join and vary with context compared to a true generative
model especially for heavy cursive styles. The new text to be created is then assembled from the
stored glyphs rather than generated from scratch, giving direct, inspectable control over scale
and spacing before anything is sent to the gantry. Extracted features like slant, spacing etc. are
also applied to the synthesised text.



2.5    Integration and testing
The integration stage formed a complete pipeline of the system through a web server, with
G-code remaining the constant fixed interface between the software reproduction output and the
gantry hardware. The web interface was designed to be able to preview and inspect generated
G-cocdes before any gantry operation was called. By previewing the gantry before reproduction,
the precision of the gantry could be measured, and any errors with gantry movement isolated.
Safety features were also included as part of the integration, which included a Emergency abort
feature on the web server to manually stop any gantry command, as well as end-stop detection
with switches to ensure the motors did not stall if the end of the rail was ever reached.

3.3.1   Plotter designs and mechanics
The chosen method of text plotting is a Cartesian gantry system with 2 independent axes of
movement with a pen up/down mechanicsm. Complex kinematics equations and error dependen-
cies are avoiding by using 2 isolated x and y movement methods for reproduction [24]. Linear
GT2 timing belts and pulleys are used to convert rotary motion from stepper motors and axles to
the desired cartesian movements. Timing belts are used for their reliability, cost effectiveness,
and higher speed travel [27].
A Cartesian gantry consists of a stationary rail that controls movement in one axis, and a movable
rail that controls the other axis of movement. For this system and future explanations, the
stationary rails control y-axis movement, while the x-axis rail moves along the y-axis. Figure 5
shows the fixed rails guiding y movement, the moving x rail and the separate pen lift.

The x-axis rail needs to move with stability and consistency, which is why it is supported on both
ends by dual-rails on the y-axis. A singular stepper motor was chosen to drive both pulleys on
both y-axis rails to ensure synchronicity and save costs. 2 independent stepper motors driving
one axis creates synchronicity issues because any difference in timing, missed steps or load
torques could offset the movement between the two motors. The challenge with using one motor
to drive two timing pulleys, is finding a method to extend the shaft of the motor to connect to
both timing pulleys without overloading the motor and applying too much tortion or twist to the
new axle. A rigid coupler was used to extend the axle of the stepper motor to a chromed steel
rod.
To reduce strain on motors, and allow for increased accuracy and precision, linear bearing were
fitted around the chromed rod rails to allow all parts to slide with very little friction. To verify
the stepper motor could handle the weight of the x-axis rail further, the torque required to move
the rail at the desired speed was calculated. It is described in Section 3.3.2 with the descriptions
of the stepper motor type chosen and its product specifications.

3.3.2   Stepper motor and driver
A stepper motor does not continuously turn with a PWM input, but rather turns at specific fixed
angles each time there is a switch in the windings (the coils of the stepper motor). The A4988
regulates the winding current through a process called chopping, which switches the current
supply on the winding until the current rises to a certain point, and then switches off at the target
current. This occurs at high frequencies and effectively keeps the current going to the coils within
a specific range so as to not overshoot, even when the motor is not actively stepping. A step is
created by slighty adjusting the current value between 2 coils just enough to allow the rotors teeth
to make a small jump or ’step’. The stepper motor is perfect for the precise movements required
for handwriting reproduction with the gantry, as it produces steps at exact, known intervals, with
position tracked from commanded steps rather than an encoder. This assumes that the motors do
not miss steps.
Two stepper motors are used in the gantry plotter, one for x and one for the y-axis direction. The
type of stepper motor chosen was the 42BYGH40-01 Nema 17 bipolar stepper motor, with a
resolution of 200 full steps per revolution and a current rating of 1.68A per phase [28].
The following calculations were done to determine if the Nema 17 stepper motor would be strong
enough for the use case of the gantry plotter, and if a singular motor could control both y-axis
belt drives safely.
Dziedzic et al. examined samples written at 10–60 mm/s [29]. The maximum handwriting
speed mentioned was 3600mm/min, which was rounded up to 4000mm/min for headroom and
approximately 10% tolerance.

3.3.3   Step resolution, microstepping and calibration
Three properties of a stepper drive fix the resolution of this machine. The motors used here take
200 full steps per revolution, so one full step is 1.8○ ; because position is simply the number of
steps that the motor was signlalled to produce, with no encoder or feedback loop required to
verify this due to the consistent nature of the stepper motors. The driver subdivides each full
step by microstepping: rather than switching the two windings fully on or off, it holds them at
intermediate current ratios, placing the rotor at intermediate angles in the stepper motor. At the

3.3.4   Pen up/down mechanism
The pen-lift mechanism itself is a design choice justified against the alternative of a third stepper
or a servo motor. A servo motor expects a continuous pulse-width-modulated position command
and typically needs its own timer a precisely timed software loop running concurrently with the
gantry’s own step timing, competing for the same processor cycles that generate STEP pulses.
An N20 geared d.c. motor run in one direction only, with a cam that toggles the pen up or
down every 90○ of rotation, needs only an on/off drive pulse of roughly known duration and
a microswitch to act as the feedback loop to verify the pen up position. It is cheap, widely
available, has high torque at low speed because of its internal gearbox, has an incredibly small
profile, and has no accuracy or positioning cost due to the use of a switch for the feedback loop.

3.4      Page conditioning and line segmentation
The recogniser needs one line of text at a time. A photographed page can contain shadows,
rotation and strokes extending between lines. This stage prepares the page and returns ordered
line crops while preserving the shape and spacing of the writing.



3.4.1     Lighting normalisation and ink extraction
Using a single global brightness threshold can mistake a shadow for ink if the page lighting differs.
The design compares each pixel with its local background, following the local comparison used
in adaptive thresholding, by calculating the background level for an area around each pixel [7,
pp. 2–3]. Image analysis uses a 0-255 grey image at half the resolution in each dimension by
averaging 2 × 2 blocks. This is to ensure thin pixel lines get do not get missed. The full-resolution
page is kept for the final crops.

Estimating the local background. The local background light level Br is the average light
level of the background of a square window of radius r around each grey pixel. The implemented
radius is r = max(8,min(40,round(H/41))), where H is image height. A summed-area table S,
also call an integral image is a pre-calculated grid where each pixel stores the sum of all pixels up
and to the left of it. It is used to calculate each window sum using four different image integral
computations to isolate the window size in the middle. [7, p. 2].
                                   Σ[y0 ,y1 )×[x0 ,x1 ) = S(y1 ,x1 ) − S(y0 ,x1 ) − S(y1 ,x0 ) + S(y0 ,x0 ).                                  (12)

a score improvement by a factor of 1.35, which will avoid an unnecessary rotation when the
evidence is weak and the facotr is not high enough.

3.4.3   Line detection and separation
To properly separate a line, a line centres is used to locate the writing, while curved boundaries
separate overlapping ascenders and descenders. A straight horizontal cut can split these strokes
even when they belong to different lines, which is not ideal, hence the reason for the curved
boundary cuts over ascenders and descenders.

Removing marks and locating line centres. A preliminary line pitch P (the estimated spacing
between text lines) sets the scale for filtering the surrounding background artifacts on a scanned
page image, and printed rule lines (the straight horizontal lines going across the page). Horizontal
and vertical run limits are 1.25 and 1.4 pitches. The pitch is estimated again after these marks
and artifact components have been cleared out. A long handwritten underline can also meet a
rule-removal condition if it remains within the specified pitch angles.
The final smoothed row profile is created and consists of candidate peaks above 6% of its
maximum. Median peak spacing gives the preferred pitch of the lines, with a lower bound based
on component height. Autocorrelation and component height provide fallbacks. Centres are
selected by peak strength (the max text height within its local range) with at least 0.6P separation.

Finding a boundary between lines. A boundary follows a low-cost path across each gap
determined by the line centers and pitch. The local cost combines a strong penalty for crossing
ink with a weaker attraction towards midpoint ym , scaled by half-gap height hg .

Crops are constructed from the original resolution picture after ownership is settled. A soft ink
mask stays away from jagged edges, while a separate nearest-neighbour ownership exclusion

therefore is able to reduce solid-shadow crops without actually checking that every remaining

3.5     Neural network design, training and classification
Two trained networks networks are used to identify the text and writer of each line. Both extract
features of the text with the same convolutional architecture, but their trained weights and output
heads are separate. A ’head’ is the last section of the model which converts the abstract features
learnt by the model into the network’s final prediction. The text reader using a CNN and BiLSTM
sequence model based off of research, implemented from first principles. [12, pp. 4–5]. The
writer head combines features across the line, also implemented from first principles. The
literacture review explores explanations about the different types of classifiers and the layers
within it.



3.5.1   Training data, labels and evaluation separation
IAM lines [4] and photographed samples provide transcripts and writer labels. The evaluated set
to train author classification contains six IAM writers (150, 152, 153, 384, 552 and 588) and
five personal contributors, to meet R6 of the project proposal which states the system must be
able to store minimum 10 author’s glyphs and styles at once. The personal pages were written
on paper, photographed with the USB camera model setup and paired with line transcripts.
The eleven-writer set defines the reported classifier and stored style profiles. The text classifier
however was trained off of an extended Teklia IAM dataset with cut crops that are pre-labelled.
The author classifier could not use the Teklia IAM dataset due to the fact that it was not labelled
with its author.
The writer dataset contains 517 IAM and 669 personal lines. One IAM page per writer is held out,
while a seeded 15% split selects which personal lines are used to validate the training. This gives
1031 training and 155 hold-out lines. The final common evaluation contains 156 re-extracted
lines, so it is reported separately from training validation. The text reader uses a joint corpus of
Teklia pre-cut IAM and personal lines.
The main difference between the full page IAM dataset used for author classifier training, and
the Teklia full line version of the IAM dataset, is that the full page IAM dataset was split by
author, therefore ideal for author training, yet a labelled transcript per page was not available.
Manual verification had to be done to ensure the labelling and segmentation was done correctly
on the full page IAM dataset. The Teklia IAM set was split by line, and had transcriptions of the
cropped line, yet did not have the author who wrote it. This was ideal for the text classifier as the
transcriptions did not have to be manually verified to ensure accurate text to label data, and the
author was not required since it is used for training the text classifier, which is independent of
who wrote it.
Blank or unusable lines and printed prompts are excluded before pairing crops with labels.
Augmentation stays within the training partition, to reduce overfitting on lines not trained on.
Both the author classifier and the text classifier were verified against their own respective hold
out pages, since they were not necessarily the same pages or lines, since the text classifier was
trained without knowledge of the author who wrote it, while the author classifier had to.

3.5.4   Writer identification and stroke normalisation
The writer head averages the 160 feature columns into 128 values and does not use a recurrent
layer, because the writers depend directly on the extracted features, and not time units or extended
like context. A 96-unit hidden layer, ReLU and a K-class output identify the writer. Dropout
probability of 0.2 is only used during the training of the network [16, pp. 1931, 1934].
The first classifier used the ink styles and thickness from the page scans directly to classify authors.

its ink size consistent, therefore this kind of system is inadequate to be tested with reproduced
text. The later classifier therefore uses normalised strokes (with the ink levels standardized for
all authors) so that original and reproduced writing are compared more through their geometry.
Binarisation, Zhang-Suen thinning and square dilation form are used to form that input, as the
following equations describe respectively: [26, p. 237], [37, p. 533].

3.5.5   Training procedure and model selection

scaled with variance, and initial normalisation scales of one with zero offsets. Augmentation is
applied to the training data to create richer model with minimal overfitting, in the form of shear,

preserving labels. Validation uses a fixed preparation path without augmentation or dropout.

3.6     Style extraction and handwriting reproduction
The reproduction stage extracts single character, or glyphs from labelled handwriting, stores
each writer’s shape and spacing measurements, and then synthesizes them into new text.



3.6.1   Choice of reproduction representation
A glyph profile reuses the few labelled pages available for each author in the personal or IAM
datasets. Haines et al. used approximately four A4 pages in their glyph-based experiments [23,
p. 4]. The new sentences can be synthesized and created without the need for a heavy weight
classifier trained on large amounts of data for reproduction, and is then mapped to the gantry.
The photographs contain no measured pen order, speed or pressure, unlike the trajectories
required by recurrent synthesis [3, p. 18], because the system used in this project was an offline
system, performing computer vision on static images. Text synthesis that is based on image
generatoration can work real time with very few existing style references as data, but the issue
is an entire model still needs to be trained on much data, and requires a significant amount of
computation to train the model well, for example on IAM-based synthesized image generator
used 339 writers and four RTX 3090 GPUs [22, p. 9]. The chosen glyph approach fits the
available data and compute, but has an expected weakness of performing glyph extraction on
heavily connected authors. Various methods were implemented alongside the glyph extraction
and synthesis, to improve the quality of reproduced writing.

3.6.3    Skeleton tracing and pen path construction
The process of thinning is used to convert an ink area into a one-pixel centreline, effectively
reducing the thickness of any ink feature to one pixel width [26, p. 237]. The complete line
is thinned first before its cut into cells, to avoid an artificial thinning boundary generated at
every letter. A graph tracer is used to divide paths at intersections, and eliminates short text
artifacts and rejoins compatible ends that are below a 75○ continuation angle. The Douglas-
Peucker simplification removes unnecessary vertices within a bounded deviation [25]. It works
by drawing anchor lines betweem two ends of a line of text to create, and then finds the point
of the text further away from the anchor. If the point is further than a limit value, the point is
kept and made to be a new vertex. The Douglas-Peucker algorithm is mentioned in the literature
review.
Dots that are on their own are recovered as short paths, and eligible detached crossbars (like for
a ’t’ shape) are assigned to their letter rather than split across cells or counted as cursive joins

3.6.4   Glyph selection and library quality
Alignment can place a cut inside a letter even when the text is correct, making the letter unusable,
and is then an unreliable glyph. The profile therefore filters out and removes unreliable lines and
glyphs using width, height, stroke count, path length and allocated character advance. This is
why it is beneficial to have more lines and pages of training data to extract glyphs from, as it
presents a higher chance of producing a decent looking glyph. Ordinary widths are limited to
2.1 x-heights and wide letters to 2.9. Distributions that are specific to certain characters provide
further checks without forcing every letter to the same size.
A normalised 12 × 12 occupancy descriptor compares shape. A pooled character reference
identifies cuts that are done incorrectly, while pairwise distances within a writer’s pool identify a
representative real variant, called the medoid. A mediod is effectively the geometrical average of
multiple extracted glyphs, to produce the ’average’ glyph for a specific character. A separate
denoised prototype combines compatible strokes. The ordinary pool holds up to twelve variants
per character. Algorithm 3 shows where these checks are done when creating a new profile.
The descriptor distance is d(g,c) = 1 − vTg rc for unit-normalised glyph descriptor vg and class
reference rc . The medoid is used to minimise the differences betweem the glyph distances per
class.

Algorithm 3 Labelled handwriting to a persistent writer profile
Require: Labelled original lines L, trained reader and writer identifier.
  1: G = null; S = null
  2: for each (G,l) ∈ L do
  3: A = ForcedAlign(G,l); estimate baseline, x-height and slant
  4: if alignment or body band is unusable then continue
  5: Refine shared increasing cuts, thin full line, and trace skeleton paths
  6: Split paths at cuts, assign crossbars, recover untraced dots
  7: Normalise glyph coordinates, and record advance, lead and boundary crossings
  8: Append glyphs to G and line measurements to S
  9: end for
 10: Cache raw extraction; reject low-confidence lines relative to this writer
 11: for each character’s glyph pool Gc do
 12:   Apply size, height-class, path-length and cell-consistency gates
 13:   Refine size range, and apply cross-writer prior and within-writer consensus
 14:   Rank and smooth retained variants, and construct medoid and eligible prototype
 15: end for
 16: return persistent profile containing G and robust summaries of S

Missing characters can use case-related shapes, similar forms or fallback glyphs, known as

3.6.5   Writer style measurement and storage
A profile of each author’s features is created per author, which stores slant, x-height, ascender
and descender extent, character advance, word gap and percentage connectivity coefficient. Slant
is estimated by finding the shear that concentrates ink into columns, and dimensions of the text
are normalised by x-height to reduce the dependency on the resolution of the image taken.

bounded slant and extent corrections before synthesis.

3.6.9                      Reproduction design limitations
Most of the design limitations with the software part of text reproduction come from the engin-
eering decision to use glyph-based text synthesis over a generative model. The reasons why a
generative model was not used was discussed at the beginning of the section. The fundamental
limitation with glyph extraction is the difficulty faced when attempting to perform forced align-
ment and single character glyph extraction on a heavily connected or cursive style. Through
techniques like the glyph anchor usage when extracted glyphs fail, the connectedness coefficient,
and reapplication of extracted author’s features, allow some clean cursive variants to perform
well. Heavy cursive is still a barrier and if more data and computational power was available, a
generative model should be looked into to perform sentence generation.



3.7                       System integration and embedded operation
A web server was created to connect page processing, models, profiles and motion control to the
browser. Training was done through the ODROID N2+ for the text and author classifiers, but
was not part of the website, as there was no use to start a new training run in a user interface
if the models and weights were already trained. Adding new authors through a user interface
was out of the specifications of this project, and new glyphs extractions, feature extractions and
author classifiers are trained through the terminal or by running a script on python, all on the
ODROID N2+.

3.7.1   Classification and reproduction workflows
Captured and uploaded pages use the same preparation and recognition path. The image condi-
tioning and segmentation code is run when a new classify request is started, and then the page
and its crops are passed into the text and author classifiers alongside its expected transcription
and author, and a percentage accuracy metric is displayed for it.
Each generated job stores paths, a preview, G-code and metadata. Drawing requires connection
and calibration, allowing preview inspection before execution.



3.7.2   Embedded execution, interfaces and job control
The pulse loop checks aborts and confirmed end stops. A separate request thread accepts
stops during drawing. End-stop faults trigger the configured recovery. Job records distinguish
generation, refusal, completion and interruption. Software stops do not independently disconnect
motor power.



3.7.3   Integration verification and remaining constraints
Interface checks cover input consistency, profile mapping, G-code bounds and interruptions.
Diagnostic retracing bypasses recognition and synthesis. Comparing its preview with the drawing
separates extraction faults from execution faults.
Stage timings separate processing, inference, generation and drawing. Reproduction totals
include generation. Results evaluates accuracy and embedded runtime.

5. Discussion



5.1     Critical evaluation of the design


5.1.1   Interpretation of results
Since the classifiers were verified to work accurately in the results, and the classification subsys-
tem was mostly independent to that of the text reproduction, it was used to verify the production.
Of course accuracy errors present in the classifiers would degrade the classification results of the
reproduction accuracy, since it cannot meet the 95% requirement itself. The author classifiers had
a higher accuracy and could therefore be trusted more. Since the classifiers are still technically
within the same system, the geometrical correlation was done in conjunction to it.
The system reproduces eleven stored styles, with 84.41% physical character recovery and correct
author identification on 86.41% of lines. All fourteen page pools are identified correctly. Seven
writers exceed 85% character recovery, which shows that the performance depends on the selected
style. It was seen that cursive writers, and more heavily connected author styles had a lower text
recognition accuracy on the reproduced text, due to the engineering decision to implement a
glyph extraction text synthesis method over an image generation method. On lightly connected
or disconnected author styles, the text classification on reproduced text exceeded requirements.
Pooling provides more writer evidence than a short line, but does not correct unreadable letters.
The geometric test gives 86.68% agreement relative to the writers’ own natural variation. Its
83 repeated words provide a separate physical-shape check, alongside classifier results. The
shorter-word subset and its 83.65% to 89.65% conditional interval limit a claim that all output
meets the stylistic target. Recognition and direct shape measures remain complementary because
recognition-based evaluation depends on its model [42, p. 2]. This is comparable to the author
classifier’s 86.41% accuracy.
The first principles scratch text classifier only achieved 94.39% accuracy, instead of the desired
95% of the specifications. This could be due to the fact that the segmenter was made from first
principles, and to be light wieght to perform classification in real time. The segmenter rarely had
issues where it would pull a descnder into the wrong crop when cutting the crops. This would
influence the training and line vs transcription. The personal dataset had to also be manually
transcripted which could produce human error which could influence the training. The first
principles stroke-normalized author identification oreaches 98.08%. This was done per line on
the hold-out pages, amoungst the 11 authors the system was trained on.
All 25 completed drawing requests meet the speed requirement, due to the design of fast and
precise mechanical movements of the gantry, and plotting methods to simplify the pen path
required to complete characters. Classification remains the main timing shortfall. The ODROID
classification runs exceededed their allowance. This mostly due to the time required to complete
first principles image conditioning, line segmentation, text classification forward propagation, and
author classifier forward propagation. Given more budget possibly a better, more capable SBC
like a Rock5B or Jetson Nano could perform the processing faster and meet the specification.



                                                                                                       64
D.R. Braune                                                                               Discussion



The measured batched-library benchmark reduces combined network time by a factor of 2.76.
Applying that gain to unchanged ODROID image times would bring L3, L4 and L5 within
their limits. C++ implementations were also tested yet the first principles code relies heavily
on Numpy already which is incredibly efficient, so converting to C++ had diminishing returns.
Lowering resolution is also unsuitable where it removes lines.
All 70 dimensions are within 0.5 mm, with a maximum error of 0.49 mm. This supports the
calibrated transmission, but the 0.01 mm minimum margin is small. A vernier caliper with a
resolution of 0.02mm resolution ensures the results were taken accurately. This proves the gantry
can achieve precise movements within the 0.5mm tolerance as specified by the proposal. The
high accuracies can be attributed to the calibration sequence, microstep movements of the stepper
motors, and the lower friction movement of the gantry.



5.1.2   Critical evaluation
Line-based CTC recognition avoids requiring correct character cuts before reading [14, pp. 2–3].
Its main dependency is correct line ownership. Clipping an ascender or including a neighbouring
line affects the crops that are supplied to the text classifier as mentioned earlier.
The glyph library suits static samples and limited writer data [23, p. 4]. It gives direct control
of geometry without requiring the recorded pen chronology used by trajectory generators [3,
p. 18]. Its weakness is contextual shape. Cursive letters change with their neighbours, and
their connection point and letter shapes change drastically, so combining isolated glyphs cannot
recover every join for heavy cursive writers. Contextual variants address this more directly than
additional random trials.
The numerical implementation makes the network calculations inspectable. Similar validation
scores and operation checks support its implementation, while batching offers a way to reuse
the maths more efficiently. The shared gantry shaft similarly reduces independent alignment
decisions and desync issues if two motors were used instead, as discussed in the design section.
Open-loop control still cannot detect a missed step after calibration, since the stepper motors do
not use encoders and can produce precise step sizes. Controlled acceleration, consistent pulse
timing and a firmer holder are appropriate improvements. A better SBC could be used to improve
computation power and timing specs, yet the R5000 budget of a hardware intense project does
not leave much room for an expensive SBC.



5.1.3   Unsolved problems
The priorities are faster classification with unchanged crops and predictions, better contextual
glyphs for connected writers, and possibly a text generative model to reproduce all types of
writing equally and accurately. Each change should be checked against the same inputs before
a new integrated qualification. Given more processing power, more intensive segmentation
techniques could be considered, for example generating a bounding box around each individual
pixel and character, to solve the error of the occasional misownership of certain ascenders and
descenders.

5.1.4   Strong points of the design
The project connects offline samples to physical output in eleven styles, capable of producing
clean cursive styles accurately without a generative model. Source crops, stored paths, G-
code and drawings make the process inspectable. Classifiers, direct geometry and dimensional
measurements provide different checks on the same system. The gantry proved to be consistent
and reliable while still remaining under the specified budget of R5000.



5.1.5   Expected failure conditions
The system can be expected to perform sub-par when reproduced strongly connected cursive
styles with heavy slant and strange features, attempting to reproduce author with not enough data
and missing glyphs, and trying to segment pages with heavy overlap between lines.



5.2     Considerations in the design


5.2.1   Ergonomics
Capture, writer selection and preview reduce repeated setup. The operator must still secure the
sheet, calibrate the axes and check pen clearance before execution, which is done automatically
to allow ease of use. Clear job and interruption feedback is necessary in case of emergency or
error.



5.2.2   Health and safety
Moving belts and carriages create pinch points, which is why the end-stop and emergency stops
are in place. Accessible motor-power isolation is needed alongside software aborts. The pen
circuit would benefit from the inductive protection described in Design [43].



5.2.3   Environmental impact
The SBC was borrowed for no cost, and will be returned to the original owener. Motion
components and the gantry can be reused. Replaceable and modular printed supports and
previews reduce discarded parts and trial pages. Training from first principles over many days
used heavy electricity consumption.



5.2.4   Social and legal impact
Personalised writing may assist correspondence, but can also imitate another person’s hand-
writing. Use should be authorised and machine output identified. Samples and profiles require

6. Conclusion



6.1    Summary of the work completed
A handwriting robot was designed and built to recognise photographed handwriting, identify
a known author and reproduce new text in that author’s style. Page conditioning and line
segmentation created crops which were passed into the text and author classifiers. Labelled
samples supply stored glyph trajectories, which are arranged into G-code and synthesised
sentences and executed by the calibrated Cartesian gantry. Eleven profiles were demonstrated in
physical output.



6.2    Summary of observations and findings
Original-line validation gives 94.39% character accuracy and 98.08% author identification.
Physical reproduced output gives 84.41% character recovery and 86.41% line identification, with
all fourteen page pools identified correctly. The separate geometric comparison retains 86.68%
of measured natural agreement on 83 repeated words. This supports useful style retention while
showing that recognisable identity does not imply identical letter geometry.
All 25 completed ODROID drawing requests meet four seconds per character. All 70 measured
feature lengths are within 0.5 mm, with a largest error of 0.49 mm. Complete classification
remains outside its time allowance on the recorded ODROID tests. A measured 2.76-fold network
acceleration provides a credible improvement route, but complete embedded compliance requires
further measurement and image-processing work.



6.3    Contribution
The project demonstrates a complete path from static handwriting samples to physical output
in multiple styles, including clean cursive styles, without the use of a generative reproduction
model. Its first-principles network implementation, explicit glyph geometry and direct motor
control make the processing steps inspectable. Classifier scores, natural-variation comparisons
and physical dimensions provide complementary evidence of the resulting performance.



6.4    Suggestions for future work
Contextual glyphs and multi-character units should improve connected styles, and text reproduc-
tion should be attempted with lightweight generative models to improve cursive reproduction.
Repeated bed coordinates and word overlays would extend dimensional verification to placement
and repeatability. Improved motor protection, acceleration control and pen restraint would
strengthen the next hardware revision.

A.2     Extended training procedure
The following procedure is the one referenced in Design.




                                                                                                   73
D.R. Braune                                                                            Supporting evidence


Algorithm 5 One numerical training batch and validation checkpoint decision
Require: Training batch, task, parameters θ and optimiser state.
  1: (X,y) ← task-specific preparation and training augmentation
  2: (F,K) ← BackboneForward(X,θ ); retain caches
  3: if task is reader then
  4: (z,Kh ) ← BiLSTMHead(F); (L,g) ← CTC(z,y)
  5: else
  6: (z,Kh ) ← WriterHead(MeanWidth(F))
  7: (L,g) ← CrossEntropy(z,y)
  8: end if
  9: gF ← HeadBackward(g,Kh )
 10: ∇θ ← BackboneBackward(gF ,K)
 11: if task is writer then clip total gradient norm to 5
 12: (θ ,state) ← OptimiserStep(θ ,∇θ ,state)
 13: if epoch is complete then
 14:     Validate with fixed preparation, stored normalisation and dropout disabled
 15:     Update schedule; save progress; replace best only if its criterion improves
 16: end if
 17: return L,θ ,state
