System Concept Definition								[     /1]

System Qualification Test Results							[     /7]
The expectation here is not a full ATP/QTP (no requirement for full procedure, list of equipment, etc) but rather the following (in table format):
A statement of the system specification to be verified 
A clear statement of the expected test results. 
The test results
No marks are awarded for the system specifications; only for accurate estimates of the expected results [/3.5] and the achieved results [/3.5]. 
Is it clear, from the description, what the expected results were? Are they specific, or vague? Are they feasible? Is there reason to suspect that the MARV would never have achieved those specs (If such expectations are presented, this section should be penalize heavily). 
Are the measured results presented in a clear and unambiguous fashion? Is there sufficient evidence of the test results? Is there reason to doubt the test results? Higher marks may be awarded for systems that meet spec, but systems that don’t meet spec shouldn’t be awarded an automatic 0 here; this mark should be about how well results are reported on, and not the quality of the results themselves.

Subsystem 1: Grading Rubric								[     /80]	
This section will count towards 80% of the student’s final exam mark. 
Subsystem Needs Analysis 								[     /4]	
Is there sufficient context to the design problem of the subsystem?
Is it clear what needs the subsystem address within the context of the system?
Is there mention both of operational and functional needs?
Does this section describe the subsystem that was implemented? If so, penalize heavily (even 0). This discussion must discuss the problem abstracted from the proposed solution.	
Subsystem Concept Exploration								[     /4]
Are there sufficient literature references to different concepts that could address the above system need?
Are sources cited and listed in the document section 1.2?
Is there evidence of critical analysis of the sources?
Does this section only describe the specific subsystem that the student implemented? If so, penalize heavily (even 0). 
Subsystem Concept Definition: Planning							[     /10]	
This must be an interpretation, rather than a duplication, of the prescribed subsystem definition; exact copies, which were not adapted to the unique system, will receive 0 marks.
Is the subsystem’s functionality captured in a single diagram? Does it contain erroneous hardware blocks? Are the natures and directionalities of internal and external interactions clear? Can you “see” the functionality of the subsystem when looking at this diagram? Is it a functional block diagram, and NOT a functional flow diagram / flow chart? [/5]
Is the subsystem’s architecture effectively captured in a single diagram? Does it contain erroneous logical / flow chart / decisionmaking blocks? Is it clearly indicated which blocks are developed and which are bought off-the-shelf? Does the architecture diagram serve as an effective plan for proceeding with the development of the subsystem? Can you “see” the physical subsystem and software architectural blocks when looking at this diagram? [/5]
Subsystem Engineering Design								[     /40]	
Are design constraints and trade-offs presented? [/2.5] for design constraints, [/2.5] for explicit references to trade-offs. 
Is there appropriate mention and motivation of the appropriate engineering tools (hardware tools, simulation packages, etc),? [/5]
Is there appropriate reference to engineering develop methods? [/10]. These can include design methods (agile, waterfall, spiral, V-shaped, etc.), prototyping, simulation, verification, and the like. Is it clear that the student attempted a systematic design method, and not an iterate-until-it-works approach? 
Is there clear evidence of both simulation and physical implementation? 
Are the requirements for a circuit / code section stated, with high-level inputs and outputs? Is it clear what is expected from the circuit / code section? [/5]
Are component / circuit designs effectively developed through top-down definition and bottom-up implementation? Are component choices motivated by requirements? Is there clear evidence of novel fundamental design effort? [/5]
Where possible, were simulations used before hardware was constructed? This may be circuit simulation, emulation of a navigation algorithm… any kind of software use to estimate efficacy / performance of a design prior to implementation [/5] 
Is there a sound approach to coding and code testing in place? Are appropriate code snippets provided? Are these evaluated for correctness? [/5] 
Subsystem Qualification Tests Results 							[     /6]	
NB! The performance of the hardware under test is NOT evaluated here. What IS evaluated is student’s ability to set and execute tests engineering tests, as well as report on test results.
This section should take the form of a table. 
The expectation here is not a full ATP/QTP (no requirement for full procedure, list of equipment, etc) but rather the following:
A brief statement of the specification to be verified, as per the MARV practical guide
A clear statement of the expected test results, based on the student’s design effort.
Indication of the test result 
It is clear, from the description, which specification will be verified? Is the specification clear and unambiguous?
Is it clear, from the description, what the measured or analysed result should be?
Is the test presented in such a way that the result can be ascertained unambiguously?
Are results provided?
