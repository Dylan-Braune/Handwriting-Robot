# File Inventory — Handwriting Robot Repository

Audited 2026-09-19. Covers every `.py`/`.ino` file under `Software/`, top-level
docs, and other genuinely relevant code. Dates are `git log --follow
--diff-filter=A` (created) and `git log -1` (last updated), both on the file's
path. `NOGIT/` (git-ignored generated artifacts — weights, caches, vendored
third-party model repos) and `Data/Datasets/` contents are out of scope except
for one-line summaries.

## Big picture

The **current, correct end-to-end pipeline** (data flows top to bottom):

1. **Label prep**: `Software/CNN/DatasetPrep/regenerate_labels_with_alignment.py` writes the real `_labels.txt` files IAM pages are trained from (its two read-only predecessors, `generate_boxes_and_labels.py`/`generate_first50_lastpage.py`, are superseded but their *output* is what got promoted).
2. **Segmentation**: `Software/CNN/ExtractIAMLines.py` (IAM-page line splitter) and `Software/CNN/SegmentPage.py` (+ `SegmentPageCore.py`, `RawImageOps.py`) for personal (non-IAM) photographed pages.
3. **Text recognition training**: `TrainText.py` (base CNN-BiLSTM-CTC, `PaperCRNN`) → `TrainTextHF.py` (same model on the clean Teklia/IAM-line dataset) → `TrainTextJoint.py` (**current best**, joint Teklia+personal training — supersedes the standalone `TrainTextPersonal.py` fine-tune, which regressed on general text). `TrainTextHF_Sweep.py` is a one-off architecture/hyperparameter sweep utility built on top of `TrainTextHF.py`.
4. **Text inference / manual OCR**: `ClassifyText.py` (interactive, loads any of the above checkpoints).
5. **Writer-ID training**: `TrainAuthor.py` (base `AuthorClassifierCNN`, ink-sensitive) → `TrainAuthor10.py` (current 10-author retrain, 8 IAM authors + 2 personal). `TrainAuthorShape.py` is the **stroke-normalised, ink-invariant** sibling model — this is the one actually used to judge synthesis, because the gantry can't reproduce ink weight.
6. **Style profile / glyph library construction**: `AuthorReproductionStuff/BuildStyleProfile.py` (core extraction) + `BuildStyleProfile10Authors.py` (wraps it for the current 8 dataset + 2 personal author set).
7. **Synthesis**: `AuthorReproductionStuff/SynthesizeHandwriting.py` — the central engine (glyph-library tiling + ligatures + jitter) — consumed by nearly everything downstream.
8. **G-code / gantry output**: `AuthorReproductionStuff/WriteGCode.py` (emission + parsing) → `WriteAsAuthor.py` (interactive end-to-end "write this text as this author" entry point) → `Software/GantryControl/odroid_direct_drive.py` (current direct-GPIO gantry driver, now with built-in G-code interpretation).
9. **Evaluation / verification** (the authoritative harnesses): `EvaluateStyle.py` (writer-ID judging), `VerifyRewrite.py` (**the main end-to-end verification entrypoint** — text + writer-ID, through the full G-code round-trip), `VerifyShapeStyle.py` (shape-only/ink-invariant version of the same), `EvaluateLegibility.py` (headline legibility+style metric on a novel corpus, uniform ink).

**Legacy / parallel / dead weight** (documented per-file below, briefly):
- `Software/StyleSynthesis/` (+ stray `Software/StyleSynthesis_tmp_style_extraction.py`) — an **early, single-author prototype** (Hershey-font base alphabet + geometric style params) that predates the whole IAM 10-author glyph-library pipeline. It imports a module (`NonDatasetSegmenterFP`) that no longer exists in the repo — **broken/dead**, superseded entirely by `BuildStyleProfile.py`/`SynthesizeHandwriting.py`.
- `Software/CNN/AuthorReproductionStuff/ReproduceV2/` — the **DiffBrush pretrained-diffusion alternative pipeline** ("revised method", image-output-only, no G-code/gantry at all). Built and left working on 2026-09-13, then not touched again while the primary glyph-library pipeline kept being developed through 2026-09-18/19. **Parked/abandoned research branch**, not integrated into the gantry-writing deliverable.
- `RNNHandwriting.py` and `StyleTransferRNN.py` (+ their diagnostics `diag_single_author.py`, `build_pw_comparison.py`, `EvaluateStyleTransferRNN.py`) — two independent from-scratch RNN generative approaches, deliberately kept as parallel experiments alongside the glyph-library method, not replacing it.
- `Software/CNN/MyHandwriting/` — a separate comparative study (methods 1-4 + `m2_*` tuning/diagnostic scripts) reproducing the *student's own* handwriting, used for the report's method comparison, not the main 10-author IAM pipeline.
- `Software/GantryControl/motion_planner.py` + `motion_simulator.py` + `motion_executor/motion_executor.ino` — the **older ESP32/serial-over-binary-frames path**, last touched 2026-08-23, superseded by `odroid_direct_drive.py`'s direct-GPIO approach (2026-09-18).
- `Software/CNN/TestsForReport/Test1TextClassify61%personal/` — a frozen **archival snapshot** (code + weights + test outputs) of an early 61%-personal-accuracy milestone, kept as report evidence, not live code.
- `Software/ComputerVision/`, `Software/WebDisplay/` — empty placeholders (`temp.txt` only).
